What happened

The honest versionTwo things went wrong, and one of them is on the guide. First: the guide's "rename the control inside the card" instruction wasn't explicit enough about the difference between a card's tree row and the control's tree row — so two cards got renamed instead of their controls, and every one of the five App Checker High errors traces to that single mix-up. Second: the SharePoint list was extended rather than rebuilt, so it drifted from the guide's names in a handful of places. This page is the complete corrective path — nothing here is new building, only fixing. The full guide series stays canonical; its red FIX boxes match these steps one-for-one.
The one concept behind most of this pageIn the tree view, a data card sits directly under frmSubmit, and the control you type into sits one level deeper inside it (default name DataCardValueNN). Formulas like .Text and .Value only exist on controls — a card with a control's name breaks every formula that references it. When any step below says rename, expand the card with its chevron and click the inner row first.

How to rename anything

  1. Find it in the Tree view (left rail). Cards live under frmSubmit; expand a card with its chevron to see the controls inside.
  2. Click the ⋮ that appears on the row → Rename (or double-click the name).
  3. Tap the amber chip here, paste it in, press Enter. Exact spelling matters — every formula on this page references these names.

How to set any property (Visible, Update, Required, AccessibleLabel…)

  1. Select the control or card in the Tree view.
  2. If it's a card and the right pane shows a padlock: open Advanced → Unlock to change properties first.
  3. Open the property dropdown — top-left of the formula bar — and pick the property named in the row.
  4. Select everything already in the formula bar, delete it, and paste the value from here. Paste only the value — never the property's name.
