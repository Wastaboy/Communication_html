What Part 3 builds

TL;DRA second screen, scrMyRequests: requesters see their own submissions with live status colors and CCD notes, and can reopen any request for editing — the shared form from Part 2 learns an edit mode. Every edit still lands in version history automatically.

Before you start

Prerequisites

  • Part 1 and Part 2 finished.
  • The app open in Power Apps Studio with at least one TEST item submitted (b11).

C7Return after edit

Replace frmSubmit's OnSuccess (the b9 version) with the edit-aware final:

frmSubmit · OnSuccess

If(IsBlank(gblEditItem), ResetForm(frmSubmit); Navigate(scrDone, ScreenTransition.None), Notify("Changes saved.", NotificationType.Success); Set(gblEditItem, Blank()); ResetForm(frmSubmit); Navigate(scrMyRequests, ScreenTransition.None))
Two exits, both explainedA new submission still gets the full confirmation screen. An edit doesn't detour — a "Changes saved." toast and straight back to My Requests, where the updated row is already showing.
Check before moving onFormula accepted with no red squiggles.
C8Edit-aware cancel + the second next-step button

Cancelling an edit should return you to your list, not strand you on the form. Upgrade the two b10 formulas:

If(frmSubmit.Unsaved, Set(gblShowCancelConfirm, true), ResetForm(frmSubmit); If(!IsBlank(gblEditItem), Set(gblEditItem, Blank()); Navigate(scrMyRequests, ScreenTransition.None)))

btnDialogDiscard · OnSelect (replaces the b10 version)

Set(gblShowCancelConfirm, false); ResetForm(frmSubmit); If(!IsBlank(gblEditItem), Set(gblEditItem, Blank()); Navigate(scrMyRequests, ScreenTransition.None))

C10F5 test — the edit loop, cancel included
  1. F5 → My requests → select the b11 TEST item.
  2. Edit this request — the form opens pre-filled, titled Edit request; the button reads Save changes and the hint reads "Ready — saving updates your request instantly…".
  3. Change Request Details, then Cancel changes → the discard dialog appears → Discard → you land back on My Requests, the item unchanged.
  4. Edit this request again, change Request Details, click Save changes — toast says Changes saved. and you land back on My Requests.
  5. + New request → submit a fresh TEST confirm - delete me later → the confirmation screen shows both buttons → View my requests lands here with the new row on top.
  6. In the SharePoint list, open the edited item's Version history — a new version, your name, right now.
Audit trail, already workingEven before the Part 5 flow exists, FR-3 + FR-4's core promise (edit after submit; every edit tracked with name and time) is being kept by version history — and a discarded edit correctly leaves no version behind.
Check before moving onAll six sub-steps behaved as described — especially: Discard reverted, Save changes stuck, and the confirmation screen offered both next moves.
