Before you start

Prerequisites

  • Part 1 finished — both lists exist and the TEST - delete me later item is still there.
  • Access to make.powerapps.com in the BBK environment.
  • Your site URL from a1 handy.

The steps

B1Create the app
  1. Go to make.powerapps.com and sign in.
  2. Check the environment picker (top-right) shows the BBK environment you build in.
  3. Click + Create → Blank app → under Blank canvas app click Create.
  4. App name: Communication Briefing Form. Format: Tablet. Click Create.
Check before moving onPower Apps Studio opens on an empty Screen1.
B2Connect the data
  1. Left rail: click Data → Add data.
  2. Search SharePoint and pick the SharePoint connector.
  3. Paste your site URL into the connection box (or pick the site from Recent) and click Connect.
  4. Tick Communication Requests → Connect.
First-run sign-inThe first SharePoint connection asks you to sign in — pick your BBK account. This is normal, not an error.
Check before moving onCommunication Requests is listed under Data in the left rail.

B5Pick and order the fields
  1. Select frmSubmit → properties pane → Edit fields.
  2. Keep exactly these five, in this order (drag to reorder): Request Subject, Department, Request Details, Target Date, Attachments.
  3. Remove Status and CCD Notes if present (⋮ next to the field → Remove).
Why no Status or CCD Notes hereThose two are CCD-managed. Requesters never set them — Status lands as the list default, Submitted, all by itself.
Attachments live inside the formThe attachment control only works inside a form bound to SharePoint. Don't drag it out of its card.
Check before moving onFive cards, in the order above, Status and CCD Notes gone.

Why DisplayModeThe button greys itself out until every required field is filled — the validation the requirements ask for, with no extra code.
Check before moving onWith Request Subject empty the button is greyed; type anything into it and the button wakes up.
B8Success and failure behavior

Select frmSubmit and set two properties (property dropdown → paste → done):

frmSubmit · OnSuccess

Notify("Request submitted — the CCD team has been notified.", NotificationType.Success); ResetForm(frmSubmit)

frmSubmit · OnFailure

Notify("Something went wrong — your request was not saved. " & frmSubmit.Error, NotificationType.Error)
Why OnFailureIf SharePoint rejects the save (connection dropped, permission missing), the requester sees the actual reason instead of a silently stuck form.
Check before moving onBoth formulas accepted — no red squiggles in the formula bar.
B9First F5 test
  1. Press F5 (or the ▷ play button, top-right).
  2. Request Subject: TEST from app - delete me later. Pick any Department, type some details, pick a target date.
  3. In the Attachments card click Attach file and add any small file.
  4. Click Submit request — expect the green toast and a cleared form.
  5. Open the SharePoint list in a browser tab: the new item is there, with a paper-clip icon and Status Submitted.
  6. Press Esc to leave preview.
If submit fails with a permission errorRe-check Part 1: a6 (item-level permissions) and a8 (you're an Owner; staff are Members).
Check before moving onItem in the list · paper-clip visible · Status = Submitted · form cleared after submit.
B10Save and publish
  1. Press Ctrl+S — if asked for a name, keep Communication Briefing Form.
  2. Click Publish → Publish this version.
Publish after every partSaved ≠ visible. Only published versions reach users, so publish at the end of Parts 3, 4 and 5 too.
Check before moving onStudio shows "All changes saved" and the publish dialog confirmed.
