What Part 1 builds

TL;DRA private SharePoint team site with a Communication Requests list (six columns, versioning on, attachments on, item-level privacy) and an Audit Log list the Part 5 flows will write to. Finish this part and the data layer is done.
Phase-1 ruleThere is no approval or rejection workflow anywhere in this build — that is a business decision by CCD, not an oversight. If you find yourself adding an approve button at any point in this series, stop.

How to read this guide

Three kinds of markers, used everywhere in the series:

  • amber chip — an exact name or value. Tap it to copy, then paste it in.
  • Navy button — something you click in the product UI (a menu, tab, or button).
  • F5 — a key you press.

Dark boxes hold longer values with their own Copy button. Every step ends with a green check — do not move on until it passes.

The steps

A1Create the team site

Everything lives on one private team site.

  1. Go to office.com, sign in, open the app launcher (top-left grid) and click SharePoint.
  2. Click + Create site → Team site → Standard team → Use template.
  3. Site name: Communication Briefing. Leave the group email alias as suggested.
  4. Privacy: Private — only members can access this site. Language: English. Click Create site, then Finish (skip adding members here — a8 does that properly).
Site creation disabled?Some tenants hide + Create site. Ask IT to create a private team site named Communication Briefing and grant you Owner — then continue from a2.
Check before moving onThe new site opens and its address looks like …/sites/CommunicationBriefing. Copy that URL somewhere handy — every later part calls it your site URL.
A2Create the Communication Requests list
  1. On the site home page click + New → List.
  2. Choose Blank list.
  3. Name: Communication Requests. Leave "Show in site navigation" ticked.
  4. Click Create.
Check before moving onAn empty list opens with a single Title column.

A5Versioning and attachments
  1. In the list, click the gear (top-right) → List settings.
  2. Click Versioning settings → "Create a version each time you edit an item in this list?" Yes → OK.
  3. Back in settings, click Advanced settings → Attachments: Enabled (it usually already is) → OK.
Why versioning matters hereVersion history is half of the audit-trail requirement: every edit keeps who and when, forever, with zero code. The Part 5 flow adds the reportable other half.
Check before moving onVersioning settings shows Yes; Advanced settings shows attachments Enabled.
A6Item-level privacy

This is the setting that keeps requesters from seeing each other's requests.

  1. Still in List settings → Advanced settings, find Item-level Permissions.
  2. Read access: Read items that were created by the user.
  3. Create and Edit access: Create items and edit items that were created by the user.
  4. Click OK.
Who still sees everythingUsers with Manage Lists permission — the site Owners you add in a8 — bypass item-level restrictions. That is exactly how the CCD team gets the full picture while staff stay in their lane.
Check before moving onAdvanced settings shows both item-level options set to the "created by the user" choices.

A8Grant access — CCD as Owners, staff as Members
  1. Site home → gear → Site permissions → Add members → Add members to group.
  2. Add each CCD member — Rawan AlQattan, Rafa Kaddoura, Abdulrahman Danish, Samar Qannati, Noora AlFaihani — and set each one's role to Owner.
  3. Then add Everyone except external users and leave its role as Member — that is what lets any staff member submit a request.
Confirm with CCD / ITAll-staff from day one, or a pilot group first? To pilot, add a smaller security group as Member instead of Everyone — the rest of the build is identical.
Check before moving onSite permissions shows the five CCD names under Owners and Everyone except external users (or your pilot group) under Members.
A9Verify the foundation
  1. In Communication Requests click + New, set Request Subject to TEST - delete me later, pick any Department, Save.
  2. Open the item again, change Request Details to anything, save.
  3. Select the item → ⋮ → Version history.
Keep the test itemPart 2's first F5 test looks for it, and Part 5's go-live step sweeps all TEST items out at the end.
