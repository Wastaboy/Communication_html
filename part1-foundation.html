What Part 1 builds

TL;DRA private SharePoint team site with a Communication Requests list (the full 34-column schema in eight groups — basics, request details, budget, PR, event, branding, and the CCD workflow — with versioning, attachments and item-level privacy) and an Audit Log list the Part 5 flows will write to. Every name and value below is tap-to-copy: nothing to retype, nothing to guess. Finish this part and the data layer is done.

How to create any column

  1. In the list, click + Add column (to the right of the last column header).
  2. Pick the column type named in that column's box below, then click Next.
  3. In the panel that slides in from the right, tap the amber Name chip here and paste it into the Name box. Paste it exactly — no spaces, no edits.
  4. Set any other rows listed for that column (choices, default value, include time). Settings not listed: leave them alone.
  5. Click Save. The new column appears at the right of the list.

How to read this guide

Three kinds of markers, used everywhere in the series:

  • amber chip — an exact name or value. Tap it to copy, then paste it in.
  • Navy button — something you click in the product UI (a menu, tab, or button).
  • F5 — a key you press.

Dark boxes hold longer values with their own Copy button. Every step ends with a green check — do not move on until it passes.

A11Versioning and attachments

Both switches live in the classic settings page — it looks older than the rest of SharePoint; that's normal.

  1. In the Communication Requests list, click the gear icon (top-right of the page) → List settings.
  2. Under General Settings click Versioning settings.
  3. Find the question "Create a version each time you edit an item in this list?" and select Yes. Leave every other option on this page as it is.
  4. Click OK — you land back on List settings.
  5. Click Advanced settings.
  6. Find the Attachments section and confirm Attachments are enabled is selected (it usually already is).
  7. Click OK.
Why versioning matters hereVersion history is half of the audit-trail requirement: every edit keeps who and when, forever, with zero code. The Part 5 flow adds the reportable other half.
Check before moving onRe-open Versioning settings — the edit question shows Yes. Re-open Advanced settings — Attachments shows Enabled.
A12Item-level privacy

This is the setting that keeps requesters from seeing each other's requests. Two radio buttons — pick them exactly as written or the privacy model breaks.

  1. Still in List settings (gear → List settings if you left), click Advanced settings.
  2. Scroll to the Item-level Permissions section — it has two groups of radio buttons.
  3. Read access — select the second option: Read items that were created by the user.
  4. Create and Edit access — select: Create items and edit items that were created by the user.
  5. Click OK.
The two traps on this pageDon't pick "Read all items" (everyone would see everyone's requests) and don't pick "None" under Create and Edit (nobody could submit at all). Both correct answers end in "…that were created by the user".
Who still sees everythingUsers with Manage Lists permission — the site Owners you add in a14 — bypass item-level restrictions. That is exactly how the CCD team gets the full picture while staff stay in their lane.
Check before moving onAdvanced settings shows both item-level options set to the "created by the user" choices.
